Problem Statement & Motivation

Centralized System Failures

2021 Twitch Data Breach: Server configuration error exposed source code, SDKs, and user data due to single point of failure.

Target (2013): Centralized storage compromised 40 million customer records.

Human Factors in Cybersecurity

  • Passwords forgotten, guessed, or stolen
  • Physical tokens (cards, keys) can be lost or duplicated
  • Biometrics: cannot be changed if compromised
  • Need for identity systems users control

Research Gap

No existing system combines: decentralized identity + trust-based access + privacy-preserving biometrics

Three Core Innovations

1. Decentralized Identity (WebID)

  • Users own personal servers with RDF-based FOAF profiles
  • No centralized authority - self-sovereign identity
  • URI-based identification with semantic web standards

2. Trust & Task Suitability (AHP)

  • Betweenness & Eigenvector centrality metrics
  • Geometric average for trustworthiness score
  • Enables organic coalition formation

3. Disposable Biometric Authentication

  • Local Binary Patterns (LBP) + Genetic Feature Extraction
  • One-time session templates - never stored
  • Prevents replay attacks, preserves privacy

WebID & RDF FOAF Profiles

How It Works

  • Each user operates a personal server
  • Profile = RDF document with FOAF ontology
  • Contains: name, tasks, performance metrics, social connections
  • foaf:knows relationships create trust network

Benefits

  • No single point of failure
  • Users control their data
  • Resilient to mass breaches

Example RDF Profile

@prefix foaf: .
a foaf:Person ;
  ns1:accuracy 0.699 ;
  ns1:reliability 0.206 ;
  ns1:speed 0.995 ;
  ns1:tasks "C", "H", "I" ;
  foaf:name "Sharon" .

Hierarchical Need-to-Know: Information visibility limited to network level - only essential data exposed for collaboration.

Trustworthiness Computation

Centrality Metrics

Betweenness Centrality: Measures how often a node lies on shortest paths between others. High betweenness = gatekeeper = trustworthy.

Eigenvector Centrality: Measures influence through connected nodes. Connected to other influential nodes = high trust.

Trust Score Formula

G(n) = √(BC(n) × EC(n))

Geometric mean of normalized betweenness and eigenvector centrality.

Trust Tiers

  • High Trust: G(n) ≥ 0.7
  • Moderate Trust: 0.4 ≤ G(n) < 0.7
  • Low Trust: G(n) < 0.4

Disposable Biometric Authentication

Local Binary Patterns (LBP)

  • Compares each pixel to 8 neighbors
  • Creates 256-bin histogram
  • Captures facial texture patterns
  • Compact & discriminative

Genetic Evolutionary Feature Extractor

  • Evolves LBP regions using genetic algorithms
  • Optimizes for accuracy & discriminability
  • Variable region sizes, overlapping allowed
  • Fitness = recognition accuracy

Key Innovation

Disposable Templates: Feature extractors generated per session, never stored. Session-specific vectors discarded after authentication.

Why This Matters

  • Templates cannot be stolen or reused
  • Prevents template reconstruction attacks
  • Privacy-preserving by design
  • Dynamic, not static identifiers

Replay Attack Resistance

The Attack Scenario

Attacker intercepts biometric feature vectors during transmission and replays them in a future session.

Why Replay Fails

  • Session-specific extractors: Each authentication uses different GEFE configuration
  • Dimensional incompatibility: Replayed vectors don't match stored enrollment vectors
  • SHA-256 token validation: Tampered payloads rejected immediately
  • Multiple extractor voting: Attack must defeat all 30 extractors simultaneously

Experimental Results

Legitimate authentications: All 17 users authenticated (100% success, avg similarity 0.998)

Replay attack attempts: 7,395 vectors tested - 0% successful match (all below 0.85 threshold)

System Architecture

Three Core Components

1. Enrollment Module

  • Capture facial image
  • Extract 30 feature vectors
  • Generate RDF profile
  • Store in databases

2. Client Authentication

  • Capture live image
  • Extract features
  • Local matching
  • SHA-256 encryption
  • TCP socket transmission

3. Server Verification

  • Decrypt token
  • Independent matching
  • Voting strategy
  • Access control decision
  • RDF profile retrieval

Data Stores

  • Feature Vector DB: User biometric templates
  • Network Registry: Users, FOAF relationships, RDF profiles

Implementation Details

Technology Stack

  • Language: Python
  • Face Detection: Haar Cascade
  • Feature Extraction: LBP with radius=8, 256 bins
  • Similarity Metric: Cosine similarity
  • Trust: NetworkX library

Communication

  • TCP socket connections
  • JSON payload format
  • Threaded server for concurrent clients
  • SHA-256 for integrity

Authentication Flow

  1. Client captures image
  2. Extract 30 feature vectors
  3. Local similarity check (threshold 0.85)
  4. Encrypt vectors + SHA-256 token
  5. Send to server
  6. Server decrypts & validates token
  7. Independent matching on each vector
  8. Voting: ≥1 match above threshold
  9. Return RDF profile if granted

Authentication Results

Enrollment & Testing

17 users enrolled across 3 subnetworks with full facial capture and 30 feature vectors each.

Legitimate Authentication

  • Success Rate: 100% (17/17 users)
  • Average Similarity: 0.998
  • Range: 0.867 - 0.981
  • At least 1 extractor always matched above 0.85 threshold
  • Client-server decisions identical in all cases

Replay Attack Resistance

  • Tested vectors: 7,395 replayed feature vectors
  • Successful matches: 0
  • Reason: Different extractor configurations made vectors dimensionally incompatible

Trust Computation Results

Fully Connected Networks (Implemented)

Issue: Automatic FOAF connections create fully connected subgraphs. All betweenness centrality = 0.

Result: Trust scores = 0 for all users (geometric mean with 0 = 0).

Limitation: Centrality requires sparse connectivity to differentiate nodes.

Erdős–Rényi Simulation

  • Setup: 3 networks, 30 nodes each, edge probability 0.3
  • Trust Score Range: 0.12 - 0.89
  • Geometric Mean: 0.47
  • Standard Deviation: 0.18

Validation

Nodes with high betweenness AND eigenvector centrality received highest trust scores. Model produces meaningful differentiation in networks with selective friendships.

Key Findings & Contributions

Hypothesis 1: Biometric Authentication

✓ VALIDATED

Disposable LBP+GEFE achieves 100% authentication with 0% replay success.

Hypothesis 2: Trust Computation

⚠ PARTIALLY VALIDATED

Trust model works in sparse networks but collapses in fully connected graphs. Requires network structure adjustment (friendship caps or weighted edges).

Hypothesis 3: Integrated Framework

✓ VALIDATED

Combining decentralized identity, trust-based access, and disposable biometrics creates a cohesive, secure collaboration platform.

Areas for Improvement

  • Adaptive thresholding for poor lighting
  • Dynamic reputation from task history (not random)
  • Weighted FOAF relationships instead of binary

Privacy & Ethical Implications

Privacy Advantages (Decentralized)

  • No mass data aggregation by central authority
  • RDF profiles, FOAF relationships under user control
  • Resilient to single-point-of-failure breaches
  • Minimal data exposure via need-to-know model

Biometric Concerns

  • Facial capture still involves sensitive data
  • Users must trust disposable templates are actually discarded
  • Cannot fully eliminate biometric data exposure risk

Trust Bias Risk

  • New users have lower centrality = lower trust
  • Structural discrimination possible
  • Mitigations needed: Transparency, appeal system, safeguards

Conclusion & Future Work

Summary

This thesis presents a novel framework integrating decentralized identity (WebID), trust-based access control (centrality metrics + AHP), and privacy-preserving biometrics (disposable LBP+GEFE) for secure collaborative networks.

Future Extensions

  • Multiple biometrics: Fingerprint, voice, iris, keystroke dynamics
  • Blockchain integration: Immutable trust scores & audit logs
  • Real task-based reputation: Dynamic accuracy, speed, reliability from execution history
  • Adaptive trust models: Weighted edges, friendship caps, temporal decay
  • Standardization: SSI (Self-Sovereign Identity) standards compliance

Impact

Enables next-generation collaborative platforms prioritizing user autonomy, trust-based cooperation, and privacy-preserving security in federated environments.
